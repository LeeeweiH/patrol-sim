# 前端说明

原生 HTML + CSS + JavaScript 实现的二维巡检仿真控制台。没有框架、没有构建工具、没有第三方 CDN 依赖，静态文件由 FastAPI 直接托管在根路径。

## 功能与环境

- 已实现的页面和操作：开场选择地图与机器人（平时收在左上角「场景」按钮里）、8×8 地图查看（障碍、机器人位置与朝向）、两种控制模式（自由移动 / 格点移动）、状态反馈（坐标／朝向／运行状态、连接徽标、中文错误提示、重新读取状态）。
- 两种模式：**自由移动**默认开启，点地图上任意位置就走过去（按住 WASD 连续走），机器人是半径 0.26 格的圆，障碍格按正方形碰撞，走到边上会贴边滑行、要绕就自动用 A* 绕开；**格点移动**退回原来的「点一次走一格」，走 `POST /api/move`，与服务端状态严格同步。
- 巡检痕迹：走过的格子会留下淡蓝色底与一个圆点，侧栏实时显示本次会话的「步数」与「经过」格数；机器人每次移动有 260ms 的滑动过渡（`prefers-reduced-motion: reduce` 时自动关闭）。
- 斜俯视舞台：地图整块向后倾 56°（约 34° 俯角，参考《植物大战僵尸》的斜俯视），障碍物与机器人改成「立牌」——底面跟着地面倾斜，图案本身反向转回来，所以始终正面朝向玩家；机器狗的四条腿在移动时摆 420ms 的一轮，停下后回到待机微动。
- 前端使用原生 HTML + CSS + JavaScript（ES2017+，无框架、无打包）开发，地图用 CSS Grid + `rotateX` 绘制，每个格子同时用颜色和「禁」「机」「货箱」图形标注，避免只靠颜色区分。
- 本地运行需要安装现代浏览器（Edge / Chrome / Firefox 的较新版本）即可；前端本身不需要安装任何依赖，也不需要 Node.js。联调需要 Python 3.10+ 运行后端（见 [后端说明](../backend/README.md)）。

## 本地启动流程

**省事的方法：** 仓库根目录有 `start.ps1` / `start.bat`，双击 `start.bat`（或在该目录执行 `.\start.ps1`）它会自动建 `backend/.venv`、装依赖、挑一个没被占用的端口起服务，再打开浏览器。想换端口用 `.\start.ps1 -Port 9000`；想让同 Wi-Fi 的同学也能访问，用 `.\start.ps1 -Lan`，脚本会打印局域网地址。

手动启动的完整步骤：

1. **进入目录。** 从仓库根目录进入 `backend/`。
2. **建虚拟环境。** `python -m venv .venv`，然后 `.\.venv\Scripts\Activate.ps1`（被策略拦住就改用 `.\.venv\Scripts\activate.bat`）。
3. **安装依赖。** 执行 `pip install -r requirements.txt`。
4. **配置后端地址。** 前端不含硬编码地址，页面和接口同源；`app.js` 内所有请求都写成相对路径 `/api/state`、`/api/move`，由浏览器按当前页面地址自动补全，因此无需配置。
5. **启动后端（前端不单独启动）。** 在 `backend/` 下执行 `python -m uvicorn app.main:app --reload`，然后在浏览器打开 `http://localhost:8080/`。`app/main.py` 已经把仓库的 `frontend/` 目录挂载到根路径，所以不需要另起静态服务器。
6. **验证页面和联调。** 页面上会先弹出开场选择（地图 + 机器人），点「开始巡检」进入。之后应看到 8×8 网格、机器狗站在 `(0, 0)`。在开发者工具的网络面板里能看到 `GET /api/state` 与 `POST /api/move`，预期状态码均为 `200`；越界或撞障碍时 `POST /api/move` 返回 `409`，页面给出中文提示且位置不变。

## 文件结构

| 文件 | 作用 |
| --- | --- |
| `index.html` | 页面骨架：顶栏与连接徽标、地图舞台、状态面板、W/A/S/D 四个方向按钮、摇杆开关与摇杆、重新读取按钮、键盘操作提示 |
| `styles.css` | 主题变量、斜俯视舞台与地图网格样式，含窄屏适配、焦点描边、禁用态、减少动效偏好 |
| `app.js` | 请求封装、交互逻辑与立牌装配，见下 |
| `assets/scene.svg` | 立牌精灵库：机器狗 `#dog`（四腿带关节，行走时摆动）、禁止通行牌 `#sign`、备用货箱 `#crate`，页面打开时内联进文档，零外链 |
| `assets/go2-lite.urdf` | 机器狗的 URDF 描述（简化宇树 Go2：13 个 link、每条腿髋/大腿/小腿三个转动关节），供后续接入真渲染器使用 |

`app.js` 的关键函数：

- `requestJSON(path, options)`：统一请求封装，8 秒超时（`AbortController`），检查 `response.ok`，解析 JSON，失败时抛出带 `code` 的 `ApiError`。
- `validateState(data)`：校验后端返回的网格尺寸、障碍物坐标、机器人坐标与朝向，结构不符直接报错，不把半截数据画到页面上。
- `renderState(state)`：按后端状态整体重建地图与状态面板；`state` 之外还接收 `{ moved, from }`，用来把「上一格 → 新格」的位移交给 CSS 做滑动动画。
- `trackPosition(state, previous)`：记录行走轨迹与步数。正常移动累加一格；若位置跳变超过一格（别的标签页移动过、重新读取时已不同步），清空轨迹重新计数，避免画出错误路线。
- `loadState()` / `move(direction)`：`GET /api/state` 与 `POST /api/move`，请求期间禁用按钮（`busy`），避免并发。
- `syncControls()`：统一控制按钮禁用状态与 `aria-busy`。
- `hits(x, y)`：圆形机器人（`ROBOT_RADIUS = 0.26`）对正方形障碍格的碰撞判定，贴边滑行靠它。
- `findPathCells(from, to)`：四连通 A*，只在自由移动模式下用，用来绕开禁止通行牌。
- `walkTo(cellX, cellY, offsetX, offsetY)`：点地图的入口。目标是格子内任意位置；点到障碍格直接提示「站不了人」，不启动寻路。
- `heldVector()`：把按住的方向键合成单位向量，支持斜着走；摇杆开着且拖出死区时优先返回摇杆方向。
- `setStick(on)` / `trackStick(event)`：网页摇杆的开关与拖动（半径取底盘 33%，死区 0.22）。开着的状态记在 `localStorage` 的 `patrol.stick`，下次打开还是摇杆。
- `stickStep(dx, dy)`：格点模式下推一下摇杆走一格，420ms 冷却，防止一次拖动走出好几格。
- `setMode(mode)` / `openSetup()` / `beginRun()`：切换控制模式、打开开场选择、按选择初始化（选择记在 `localStorage` 的 `patrol.selection` 里）。

## 控制方式

- **自由移动（默认）**：点地图任意位置走过去；按住 `WASD` / 方向键连续移动；打开摇杆开关后改用网页摇杆，键盘移动同时暂停。
- **格点移动**：按一次方向键（或推一下摇杆）走一格，走的是 `POST /api/move`，与后端严格同步。
- **摇杆开关**：`用网页摇杆移动` 打开时隐藏方向按钮、显示摇杆；关掉后方向按钮回来，`WASD` 恢复。开关状态记在 `localStorage` 的 `patrol.stick`。
- **重新读取状态**：重新拉一次 `/api/state`，并清空本轮巡检痕迹（步数归零、蓝格只保留机器人脚下那一格）。

## 交互与错误处理约定

- 前端不预测位置：格点模式下移动成功与否、移动到哪一格，一律以后端返回的完整状态为准。
- 自由移动是**页面内的运动模拟**：位置、朝向、轨迹都由前端算，不写回后端；切回格点模式会重新 `GET /api/state`，以服务端坐标为准（这一步机器人会瞬移回服务端位置，属预期行为）。
- 后端明确拒绝（`400` / `409`，如越界、撞障碍）时，提示「移动被拒绝：…」，画面保持上一次确认过的状态。
- 超时、网络异常、`5xx` 或响应格式不符时，视为「结果未确认」，页面提示点击「重新读取状态」，不会自动重发请求。
- 连接状态徽标会随请求结果切换为「服务在线／未连接服务」。

## 构建与检查

- 构建：不适用（纯静态文件，无打包、无产物目录）。
- 依赖安装：不适用（前端不引入任何第三方包）。
- 提交前的人工检查：
  1. 浏览器控制台无报错；
  2. 窗口缩到 375px 宽时地图不横向溢出；
  3. 用 `Tab` 键能依次聚焦到四个方向按钮与「重新读取状态」，回车可触发；
  4. 停掉后端再点方向按钮，应出现中文错误提示而不是页面卡死。

## 模型与换皮

当前是「2D 精灵 + 假 3D 镜头」的做法，和《植物大战僵尸》同一套思路：地面用 CSS 3D 压平，单位用贴着镜头的立牌，成本低、性能稳、以后换皮只改素材。

- **换机器狗**：编辑 `assets/scene.svg` 里的 `<svg id="dog">`（保留 `viewBox` 与 `.hip / .thigh / .knee / .calf` 这套关节结构，行走动画就还能用），或者换掉 `app.js` 里 `SCENE_URL` 指向的文件。
- **换配色**：`styles.css` 里 `.sprite .shell`、`.sprite .leg-far / .leg-near`、`--robot` 一组变量；颜色不要写进 SVG，方便做多套皮。
- **机器人朝向**：`HEADING_DEG`（地面光锥角度）、`HEADING_TURN`（立牌左右偏转）、`HEADING_FLIP`（镜像）在 `app.js` 顶部，改这三个表就能调整朝向表现。
- **URDF**：`assets/go2-lite.urdf` 是给后续接真 3D（three.js + URDF 加载器、或离线仿真）准备的模型描述，页面本身不加载它；要真渲染时把关节名字 `*_hip_joint / *_thigh_joint / *_calf_joint` 对上前端行走相位即可。
- **换角色**（以后想上明日方舟那类角色）：同样做一张 `viewBox` 一致的立牌 SVG，替换 `#dog`，把 `billboard--dog` 的宽度系数（现在 1.5 格）按角色比例调一下即可。
