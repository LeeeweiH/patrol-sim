# 设计说明

本文记录「基于 Web 的智能巡检机器人二维仿真系统」的技术设计与实现取舍，供结业验收与软件著作权登记的技术说明书使用。文中提到的函数名与常量都能在仓库里检索到，括号内是所在文件与行号。

## 1. 目标与边界

系统要回答一个问题：一个只有二维地图的巡检场景，怎样做得像"能操作的东西"，而不是一张会动的图。

范围：

- 浏览器里看到一个斜俯视的巡检场地，机器人、障碍、出入口都是可辨识的立体立牌；
- 两种控制方式（一格一格、随意走），都能正确避障、越界拒绝、状态可回读；
- 状态以服务端为准，页面不做本地预测，刷新后回到同一状态；
- 单个容器即可部署，无需数据库、无需 npm 构建。

不做：真实机器人对接、多用户并发会话、三维物理仿真。

## 2. 总体架构

```
浏览器（原生 HTML/CSS/JS，无框架）
   │  fetch /api/*
   ▼
FastAPI（backend/app/main.py）
   │  进程内单例
   ▼
Simulation（backend/app/sim.py）—— 唯一的真值来源
   │
   └── StaticFiles 挂载 frontend/，同一端口同时提供页面与接口
```

三个刻意的选择：

- **没有数据库**。巡检场景是单机演示，状态存在进程内存里足够；重启回到初始位，行为反而可预期。
- **没有前端构建**。`frontend/` 里就是三个文件加一个 SVG，改完刷新即生效，部署面最小。
- **接口只有三条**。`/api/health`、`/api/state`、`/api/move`；前端所有显示都由这三个接口派生。

## 3. 后端设计

### 3.1 状态模型

`Simulation` 持有四个字段：`x`、`y`、`heading`、`status`（`backend/app/sim.py`）。地图固定 8×8（`GRID_WIDTH` / `GRID_HEIGHT`），障碍是三处固定坐标（`OBSTACLES`），坐标原点在左上角，x 向右、y 向下。

### 3.2 移动的一致性

`move()` 的顺序固定为：校验方向 → 校验边界 → 校验障碍 → 通过后才写状态（`backend/app/sim.py:79-101`）。任何一步失败都抛异常且**不改动任何字段**，这是"失败时坐标不变"的根：

| 情况 | 异常 | HTTP |
| --- | --- | --- |
| 方向不在 up/down/left/right | `InvalidDirection` | 400 |
| 走出 0–7 边界 | `OutOfBounds` | 409 |
| 目标格是障碍 | `Blocked` | 409 |
| 请求体不是合法 JSON | 解析失败 | 400 |

错误响应统一为 `{"error": {"code": ..., "message": ...}}`，`message` 是给人看的中文，前端直接展示。

### 3.3 状态位的时间窗

最初 `move()` 把 `status` 置成 `moving` 之后就再没改回来，导致页面永远显示「移动中」。修法是在状态里记一个时刻：

```python
MOVING_WINDOW_SECONDS = 0.5
self.last_move_at = time.monotonic()   # move() 成功后
# state() 开头
if self.status == "moving" and time.monotonic() - self.last_move_at > MOVING_WINDOW_SECONDS:
    self.status = "idle"
```

用"读时判定"而不是定时器，好处是没有后台线程、没有资源泄漏，测试里也能用 `sleep` 验证；副作用是 `POST /api/move` 的响应仍然是 `moving`（符合"刚移动完"的语义），0.5 秒后再读才变 `idle`。

### 3.4 多地图（场景）

地图不是写死在渲染里的，而是由后端提供的一份数据：`SCENES` 里每张图有 `id`、`name`、`width`、`height`、`obstacles`，`Simulation` 持有当前场景，`state()` 把它一并返回（`{"scene":{"id","name"},"grid":{...},"robot":{...}}`）。

- 内置两张：`standard` 标准巡检区 8×8（3 处障碍，与最初契约一致）与 `warehouse` 仓储通道 10×8（7 处障碍，用来验证非正方形地图）。
- 切换走 `POST /api/scene {"id": ...}`：切换后机器人回到该图起点、状态 `idle`，返回切换后的完整状态；未知 id 返回 400 `invalid_scene`，message 里带可选值。
- `Simulation()` 无参时仍是 8×8 标准图，`robot` 的字段不变——保证原有测试与契约不受影响，多出来的信息只加在顶层。
- 前端地图选择器是数据驱动的：卡片上的尺寸、障碍数来自 `GET /api/scenes`，渲染按 `grid.width/height` 生成格子，所以新增一张图只需要改后端 `SCENES`。

### 3.5 巡检报告留档

自动巡检跑完就有一份统计（点位、用时、步数、新覆盖格数）。前端把它导出成 Markdown 的同时，会 `POST /api/report` 存一份到服务端内存里：

- 服务端只保留最近 50 条（`REPORT_LIMIT`），超出丢最早的一条；自增 `id` 与 `received_at` 由服务端生成，前端传的数据都要过校验（地图要在 `SCENES` 里、四个数值必须是非负数字，`bool` 不算数字）。
- `GET /api/reports?limit=N` 按时间倒序返回，用来对比多次巡检的步数与覆盖——同一张图走两遍，步数下降说明路线更顺。
- 报告存在内存里，进程重启即清空；这是有意的——结业演示不需要持久化，真要留档可以直接导出 Markdown。

## 4. 前端渲染

### 4.1 斜俯视是怎么来的

没有三维引擎，全部靠 CSS 变换：

- 舞台 `.stage` 负责透视与比例，`aspect-ratio: 1 / 0.72` 保证宽高一起缩放；
- 棋盘 `.board` 整体 `rotateX(56deg)`，得到约 34° 俯角的扁格子；
- 立牌 `.billboard` 反向 `rotateX(-56deg)` 抵消棋盘倾斜，于是"站在格子上"的精灵始终保持竖直；
- 轴向数字单独再反一次，保持可读（`frontend/styles.css` 中 `.axis` 规则）。

透视距离取 `6000px`：太近会让四角格子被拉伸得比中间大很多，还容易把最右一列顶出卡片；6000 是一个既保留纵深感、又不至于变形的折中值。

### 4.2 精灵与换皮

所有可绘制对象放在一个 SVG 精灵库里（`frontend/assets/scene.svg`）：`#dog`、`#sign`、`#gate-in`、`#gate-out`，另有备用皮肤 `#crate`。

- `loadSprites()` 取一次 SVG 并内联进文档，随后 `cloneSprite(kind)` 克隆出任意多个实例；
- `makeBillboard(kind)` 把精灵包进一个 0×0 的锚点，靠 `translate(-50%)` 让精灵底部中心对准格子中心；
- 机器狗的腿是分层结构 `.hip > .thigh > .knee > .calf`，走路时用 CSS 关键帧摆动，四条腿用 `animation-delay: -210ms` 错开成对角步态。

换皮不需要改逻辑：替换 SVG 里对应 `id` 的图形即可，这一点写进了 `frontend/README.md` 的「模型与换皮」一节。`frontend/assets/go2-lite.urdf` 是同一台机器狗的 URDF 描述（连杆树 + 关节限位），页面不加载它，作用是给后续接真三维视图留一份可用的模型定义。

### 4.3 坐标映射

棋盘有两套坐标：格子坐标（0–7 的整数）与像素坐标。`gridMetrics()` 量出棋盘原点与格距，`applyActorTransform()` 用 `translate3d` 把角色放到对应像素位置；反向的 `pointIn()` 把点击位置换算成格内偏移，供自由模式使用。所有定位都走这两个函数，避免同一套换算在多处重复。

### 4.4 自适应

早期用 JS 计算并写入 `--stage-h` 固定高度，窗口变化后高度停在旧值，页面就散了。现在高度完全由 `aspect-ratio` 决定，JS 只负责把格子边长夹在 24–170px（`fitStage`，`frontend/app.js:178`），保证极小窗口不塌、超大屏不夸张。

## 5. 两种控制模式

### 5.1 格点模式

按一次方向键（或 WASD）→ `POST /api/move` → 用服务端返回的 `state` 重绘。位置永远等于后端的位置，不存在本地预测；失败时提示原因、坐标不动。

### 5.2 自由模式

目标是可以站在格子里的任意位置，而不是格子中心。实现要点：

- 角色有连续坐标 `actor.x/actor.y`，由 `requestAnimationFrame` 循环推进（`frame`，`frontend/app.js:655`），速度 `FREE_SPEED = 2.6` 格/秒；
- 输入有三个来源，优先级为：摇杆 > 键盘 > 点选目标；三者最终都归到"当前希望移动的方向向量"；
- 点地图任意位置 → `walkTo()` 规划一条到该点附近的路径并沿路点前进；
- 自由模式的位置只在本页有效，切回格点模式会重新 `GET /api/state` 对齐到服务端坐标——这是有意的取舍，避免本地状态和真值分叉。

摇杆是纯指针事件实现：按下时记录触点，移动时算出相对圆心的偏移（死区 0.22，剩余量映射成 0.35–1.0 的速度系数），松手归零；它作用于同一个方向向量，所以和键盘不冲突。

### 5.3 自动巡检

自动巡检让机器人按固定路线自己走一遍，用来演示「不需要人手点也能跑完整场」。

- **点位生成**：`patrolRoute()` 按行扫描，每两格取一个点，相邻行反向排列（蛇形），并跳过装了禁止通行牌的格子；8 × 8 地图上是 15 个点。密度是刻意稀疏的——逐格扫描看起来像扫雷，隔行取点更像巡视。
- **推进方式**：`patrolNext()` 取队首点位调用 `walkTo()`，路径仍走 A\* + 拉直，巡检和手动点击用的是同一套避障，不存在两套逻辑。
- **状态机**：`patrol.on` 为真时，`frame()` 在「静止且没有目标」时自动取下一个点位；到达提示改成「巡检中 n/总数」，避免和手动到达提示混淆。
- **接管即停**：`walkTo()` 入口判断这次调用是不是用户发起的；按键输入在 `frame()` 里检测到方向向量时中断；`setMode()` 切换模式也中断——三条路径都收敛到 `stopPatrol()`，不会出现「手动操作了但机器人还在巡检」。
- **收尾**：队列空时 `finishPatrol()` 统计用时、移动步数与本轮新覆盖格数，把「导出巡检报告」按钮亮出来（`exportPatrolReport()` 用 `Blob` 直接下载 Markdown，不经过后端）。
- **报告内容**：生成时间、地图尺寸与障碍数、点位完成数、用时、步数、新覆盖格数、结束位置，以及一段路线策略说明——方便直接贴进结业材料或作业存档。

自动巡检是纯前端状态机，不新增接口、不改后端契约。

## 6. 运动规划与碰撞

### 6.1 路径

`findPathCells()` 是四连通 A\*（`frontend/app.js:409`），把障碍格视为不可通行，得到一串格子。之后的 `buildWaypoints()` 用"能直着走就直着走"的方式把折线拉直（string pulling），减少无谓拐弯。

### 6.2 碰撞：连续扫掠而不是采样

第一版用"每隔 0.12 格取一个采样点判断是否撞墙"，快速连点时会在两个采样点之间穿模——斜着蹭过牌子拐角时，采样点都在外面，实际圆已经压进去了。

现在的做法是解析判定：

1. 把每个障碍格按机器人半径 `ROBOT_RADIUS = 0.26` 向外膨胀，得到 Minkowski 矩形；
2. 判断线段（本帧的位移）与这些矩形是否相交，用 slab 法求交（`segmentHitsRect`，`frontend/app.js:464`）；
3. `blockedAlong()` 对所有膨胀矩形做一遍，等于"圆沿线段扫过的区域是否碰到障碍"的精确解，`frontend/app.js:508`。

### 6.3 推进

`advance(dx, dy)` 是唯一改动角色位置的地方（`frontend/app.js:593`）：先整段扫掠，被挡则拆成两个轴分别试，能走哪个走哪个（贴边滑行），都不行就停。因为判定和推进共用同一个几何函数，不会出现"判定说能过、推进却进去"的分歧。

越界同样在 `advance` 里判：`0 ≤ x ≤ width-1`、`0 ≤ y ≤ height-1`，所以自由模式下也走不出地图。

### 6.4 压测

无头浏览器里对地图连点 46 次（含点在牌子上、快速连点），逐帧记录：最小间隙 0.5 格（半径才 0.26）、穿模 0 次、越界 0 次、终态停在边界格且状态回「待命」。

## 7. 反馈与错误处理

| 场景 | 处理 |
| --- | --- |
| 后端拒绝（4xx） | 展示后端 `message`，位置不变，状态标「待命」 |
| 网络异常 / 超时（8 秒） | 提示"结果未确认"，建议点「重新读取状态」，**不自动重发** |
| 首次加载失败 | 地图区显示占位说明，方向键禁用，但「重新读取状态」保持可用 |
| 移动成功后 | 900ms 静默重读一次状态，让徽标从「移动中」变回「待命」（`scheduleSettle`，`frontend/app.js:1082`） |

不自动重发是关键决定：移动不是幂等操作，重发可能让机器人多走一格。

## 8. 可用性

- 键盘：方向键与 WASD 都能移动，在格点模式下映射为一次接口调用；按住输入框时不劫持按键。
- 无障碍：棋盘是 `role="group"`，每个格子有中文 `aria-label`（"第 3 行第 2 列，禁止通行"），按钮可 Tab 聚焦并有 `:focus-visible` 描边。
- 动效：`prefers-reduced-motion` 下关闭步态与位移动画。
- 窄屏：≤900px 自动改成上下布局并隐藏折叠把手，390px 宽无横向溢出。

## 10. 已知限制

- 自由模式的位置不写回后端，刷新或切模式会回到服务端坐标；
- 机器人是二维立牌，没有真实的俯仰与遮挡关系，重叠时靠绘制顺序近似；
- 状态只存在单进程内存里，多实例部署无法共享同一台机器人；
- 移动端没有做双指缩放，靠整页缩放代替。
